## 2. Patterns that recur across upstream installers

1. **Delegation is universal; nobody re-implements root deployment.** osbuild, Anaconda, Readymade, fisherman and `system-reinstall-bootc` all exec `bootc install to-filesystem` / `to-existing-root`; legacy paths exec `ostree container image deploy`. bootc's own `to-disk` is documented as "mainly a demo" (bootc-install.md:41-42) and lives behind the default-on `install-to-disk` Cargo feature. bootc states it is "primarily intended to be driven via a fork/exec model. The core CLI verbs are stable and will not change" (bootc-via-api.md; https://bootc.dev/bootc/bootc-api.7.html). Issues #542 (library API), #433 and #879 (run outside a container) are open.

2. **Top-half / bottom-half split.** External tool partitions, formats and mounts; bootc deploys. Sequence (Readymade, fisherman, Anaconda, osbuild): discover → partition (systemd-repart templates / sfdisk / blivet, DPS GUIDs) → mkfs → mount temp root → optional SELinux mountpoint labelling → `bootc install to-filesystem --source-imgref … --target-imgref … [--karg …] [--stateroot] [--bootloader] [--skip-finalize] <root>` → inject (`bootc install mount --sysroot <root> --latest`, main only) → `bootc install finalize` → `umount -R`.

3. **The image installs itself.** `prepare_install` requires `/run/.containerenv`, host pidns (`getpid().is_init()` rejected), host userns (rootless rejected); mirrors `/dev`, `/var/lib/containers`, `/var/tmp` (+ `/run/udev` at v1.16.14) from pid1's mountns; re-execs as `install_t`. Even `--source-imgref` "still has to be run inside a chroot created from the container image" (bootc-install.md:342-346; bubblewrap allowed). cgwalters (#1400, 2025-07-10): "I'd really like going forward in general to lean strongly into the 'run bootc install from target container' as much as possible". Canonical command: `podman run --rm --privileged --pid=host --ipc=host -v /var/lib/containers:/var/lib/containers -v /dev:/dev --security-opt label=type:unconfined_t <image> bootc install to-disk /path/to/disk`.

4. **Tiered drop-in config lives in the image.** `{/usr/lib,/usr/local/lib,/etc,/run}/bootc/install/*.toml` (liboverdrop 0.1.0; serde kebab-case + `deny_unknown_fields`; scalars override, `kargs`/`karg-deletes` append; `match-architectures` filters a file), `/usr/lib/bootc/kargs.d/*.toml`, `/usr/lib/repart.d/*.conf`, `/usr/lib/image-builder/bootc/{disk,iso,extras}.yaml`, `sysupdate.d/*.transfer`, `/etc/kernel/install.conf`. Same shape as MiOS Laws 1/13. osbuild stage `org.osbuild.bootc.install.config` writes the bootc TOML at build time — the exact Law 8 "generator emits a projection" pattern.

5. **Karg layering order (ostree backend, install.rs:1166-1205):** root-fs kargs → install-config kargs → image `kargs.d` → (config + CLI) deletes → CLI `--karg` last. UKI/composefs path forbids external kargs (`require_no_kargs_for_uki`) → use `--uki-addon`. Anaconda passes root/LUKS kargs via `--karg` and deliberately omits `--root-mount-spec`/`--boot-mount-spec` so bootc auto-detects.

6. **Capability probing instead of version pins.** bootc greps `bootupctl backend install --help` for `--filesystem` and parses `bootctl` version (≥257 → `--random-seed no`); `system-reinstall-bootc` greps `bootc install to-existing-root --help` for `--cleanup`. Suited to MiOS's floating base tag.

7. **Plan-then-apply with machine-readable dry run.** GNOME OS and bootc main run `systemd-repart --dry-run=yes --json=…` then `--dry-run=no`; Readymade parses `partitions[].node`; disko-install `--dry-run`; coreos-installer/Flatcar `-y`; the Python wrapper already has `--dry-run/--json`.

8. **Safety gates.** Refuse existing partitions unless `--wipe` (baseline.rs:223-229); `require_empty_rootdir` (only `lost+found` and mountpoint dirs; Anaconda `_clean_physroot` and Readymade `bootc_cleanup` exist solely to satisfy it); 20-second abortable spinner when target fsid == `/proc/1/root` fsid unless `--acknowledge-destructive` (install.rs:2446-2470); refuse the live boot device (Python line 312, Endless, Flatcar); `udevadm settle`/`BLKRRPART` after table writes (coreos-installer); verify-before-commit (Endless zeroes first MiB until GPG passes; Flatcar verifies on-stream; sysupdate `Verify=` default yes; bootc `--enforce-container-sigpolicy`); DMI allow-list for unattended (Endless).

9. **Declarative device selector, not heuristic scoring.** Talos `diskSelector` (size/name/model/serial/modalias/uuid/wwid/type/busPath, "Always has priority over disk"); Kairos `device:` by-{uuid,label,path,diskseq} or `script://`; Flatcar `-s` smallest ≥10 GB with major-number filters.

10. **Unattended = same config + guard rail.** tik `TIK_INSTALL_DEVICE/IMAGE`, Kairos `install.auto: true`, Endless `unattended.ini` DMI match + countdown, ChromeOS `--yes`.

11. **One declaration, two consumers.** disko `enableConfig` → `fileSystems`; Kairos `install:` is also runtime config; tik and bootc consume repart.d/install TOML shipped in the image.

12. **Bootloader auto-selection.** CLI > install config > (`bootupctl` present AND `usr/lib/bootupd/updates` → grub, else systemd). systemd-boot only with the composefs backend; `none` only with ostree; bootupd runs only at install, never day-2 (bootloaders.md:12,16,31). Sealed composefs requires a UKI + systemd-boot and NO bootupd (experimental-composefs.md).

13. **Logically bound images at install.** `--bound-images {stored (default), pull, skip (hidden)}`; `stored` copies `bound-images.d` `Image=` refs from host `/var/lib/containers` (`podstorage.rs:471 pull_from_host_storage`) into target `/usr/lib/bootc/storage`; bootc main pulls bound images before staging (df68f6c1). Anaconda does not support LBIs.

14. **Installer == live image of the same OS.** tik self-deploy, GNOME OS 2025 image, Talos installer-as-container, titanoboa/bootc-generic-iso squashfs of the container with `--bootc-installer-payload-ref` copying the image into `/var/lib/containers/storage`; kickstart `--transport=containers-storage`.

15. **Incremental de-shelling.** ChromeOS ships a Rust entry point that execs the old script and absorbs steps piecemeal; Kairos drops binary deps one at a time.

16. **Provenance.** `.bootc-aleph.json` + fixed journald MESSAGE_IDs per mode (to-disk 8b7c…, to-filesystem 9a8b…, to-existing-root 7c6d…, finalize 6d5e…).

## 3. Recommended architecture for a Rust static-pie MiOS installer

### 3.1 Shape: a static orchestrator that execs bootc (never links it)

`tools/native/mios-install` (Rust, `x86_64-unknown-linux-musl` static-pie, `+crt-static`, rust-lld, per `[build.native.linux]`), modelled on `system-reinstall-bootc` + Readymade's `libreadymade` crate split (plan model in a library crate, thin CLI binary). Three verbs mapping 1:1 onto bootc legs — the mapping ADR-0014 already names:

| Verb | bootc leg | Bottom half owned by MiOS |
|---|---|---|
| `mios-install disk <dev>` | `to-filesystem` after MiOS-driven `systemd-repart` (preferred), or `to-disk --wipe` as the compatibility path | partition (repart.d from the image), mkfs via repart `Format=`, mount root + ESP via `rustix::mount` |
| `mios-install filesystem <mountpoint>` | `to-filesystem [--root-mount-spec UUID=…] [--boot-mount-spec …] [--skip-finalize]` | none (operator-mounted) |
| `mios-install existing-root` | `to-existing-root --acknowledge-destructive [--cleanup]` | none; mirror `system-reinstall-bootc`'s command |

**Implement natively in Rust (zero C linkage):**
- Plan resolution from the mios.toml cascade via `mios-resolver` (`[image].ref`, filesystem, layout, kargs, LBI policy, device selector, unattended policy).
- Device discovery and ranking from sysfs (`lsblk` crate 0.6.1 is pure std: `/sys/dev/block/{major}:{minor}/`, `/dev/disk/by-*`, `st_rdev`) or direct `/sys` reads — no `lsblk(8)` exec, no FFI. Port the Python safety gates: refuse the device backing the live root (fsid vs `/proc/1/root`), exactly-one-candidate-or-fail, existing-partition refusal unless `--wipe`.
- Talos-style declarative selector (`[install.disk] size/model/serial/wwid/type/bus_path`, globs) replacing the NVMe>SSD>HDD score.
- Capability probing by `--help` text (bootc flags such as `--cleanup`, `--bound-images`, `--skip-finalize`; `systemd-repart --help`; `bootctl --version`), never a hardcoded bootc version (the base tag floats: 1.16.10 at bake today).
- Plan object printed by `--dry-run --json` and consumed by the executor (OpenAI-format schema per repo rule), preserving the Python contract `--yes/--dry-run/--json/--mock` and `tests/test-baremetal-install.py` expectations.
- Mount/umount via `rustix::mount` (already in the workspace lock).
- Optional in-process GPT via `gptman 3.1.1` (pure Rust) **only** as a no-systemd fallback; it duplicates repart otherwise.
- Pre/post hook runner: `/usr/lib/mios/install.d/{pre,post}/NN-*` (vendor) < `/etc/mios/install.d` (admin), tik-style; typical post hooks: write host-tier `/etc/mios/mios.d/*.toml` fragments into the target (firstboot does the rest, Law 12), copy logs to removable media on failure.
- Journald MESSAGE_IDs and a `.mios-install.json` provenance record next to bootc's `.bootc-aleph.json` (**inference**: pattern borrowed, format to be defined).

**Delegate (exec):**
- `bootc install …` inside the image container (deployment, ostree sysroot, kargs, bootloader selection, bound images, SELinux relabel).
- `systemd-repart` for partitioning/mkfs: exec `systemd-repart --dry-run=yes --json=pretty --definitions <dir> <dev>` then `--dry-run=no --empty=force --json=short`, parse `partitions[].node` (GNOME OS / Readymade / bootc-main shape). On the Fedora 44 base (systemd 259.x) the `io.systemd.Repart` Varlink interface (`Run`, `ListCandidateDevices`) is available and can replace exec with a pure-Rust JSON client; keep exec as the F43 (258.11) fallback.
- `bootupctl backend install` / `bootctl install` — never called directly; let bootc select the bootloader (CLI > install config > probe). Direct use of the hidden `bootupctl backend` verb is a bootc-only contract.
- `cryptsetup`/`systemd-cryptenroll` for `--block-setup tpm2-luks` (let bootc do it, or repart `Encrypt=` + `--tpm2-device=auto` as GNOME OS does).
- `podman` for image presence (`pull_if_not_present`) and for running the install container.

### 3.2 Install config projection from mios.toml (Law 8)

Add an `[install]` table to `usr/share/mios/mios.toml` (SSOT) and have a build-time generator in `automation/NN-*.sh` (or a Rust generator in `tools/native/`) emit, with a regenerate-and-diff drift check in `automation/98-drift-checks.sh`:

1. **`usr/lib/bootc/install/00-mios.toml`** — exactly the documented keys, because the parser is `deny_unknown_fields`: `[install] root-fs-type` (or `[install.filesystem.root] type`; nested wins when both are set — config.rs), `kargs`, `karg-deletes`, `block = ["direct"|"tpm2-luks"]`, `stateroot`, `root-mount-spec`, `boot-mount-spec`, `bootloader`, `discoverable-partitions`, `enforce-container-sigpolicy`, `[install.ostree] bls-append-except-default`, `[install.bootupd] skip-boot-uuid`, `match-architectures = ["x86_64"]` (hyphen; matches MiOS's `kargs.d` fragments).
2. **`usr/lib/repart.d/*.conf`** — ESP (`Type=esp Format=vfat`, size from `[install.layout]`), optional `Type=xbootldr` when GRUB/bootupd or tpm2-luks requires a separate `/boot`, `Type=root Format=<fs> SizeMinBytes=…` (today's `50-root.conf`), with DPS GUIDs so `systemd-gpt-auto-generator` and bootc `--discoverable-partitions`/`use-dps` can discover them. These are consumed by (a) the MiOS orchestrator's repart step, (b) bootc `to-disk` **once MiOS bakes a bootc that includes the systemd-repart branch (main only; absent at v1.16.13/v1.16.14 — see §5)**, (c) bcvk/image-builder disk images — one layout SSOT, three consumers (disko pattern).
3. **`usr/lib/bootc/kargs.d/*.toml`** — already projected; keep.
4. **Image-builder `disk.yaml`/`iso.yaml`** under `/usr/lib/image-builder/bootc/` when `just iso` migrates to `bootc-generic-iso` (**inference**: future work, not required by the installer).

ESP size must be a mios.toml value: upstream has no consensus (bootc 512 MiB; 1024 MiB composefs at 1.16.13/14, 2048 on main; fisherman 2 GiB; bootc-installer README 1 GiB; Python planner 1024).

### 3.3 Unattended / declarative install

Mirror Kairos/Talos/tik: the same `[install]` table carries `device` (path, `/dev/disk/by-*`, or selector block), `auto = true|false`, `reboot|poweroff`, `wipe`, `filesystem`, `kargs`, `bound_images = "stored"|"pull"`, `signature_policy`, and an Endless-style hardware allow-list (DMI vendor/product or serial) that gates `auto`; the CLI keeps only `--yes/--dry-run/--json/--mock/--target-disk` overrides. Resolve through the three-layer cascade so a Blade-specific host fragment can pin the disk. Whether the allow-list belongs in the vendor tier or only host/admin tier (Law 11 if serials are sensitive) is open.

### 3.4 Bound images

Default `--bound-images stored` copies LBIs from the installer host's `/var/lib/containers`; the installer must therefore either pre-pull every `usr/lib/bootc/bound-images.d/*.image` `Image=` ref on the install host (live ISO: ship them in the ISO's containers-storage — image-builder's `--bootc-installer-payload-ref` pattern) or pass `--bound-images pull` for networked installs. Make this a mios.toml policy; the air-gapped Ventoy flow needs `stored` + pre-seeded storage. Anaconda cannot do LBIs, which is one more reason not to route through kickstart.

### 3.5 Invocation model: privileged container from the image, not a host binary

- Run bootc **inside the image**: `podman run --rm --privileged --pid=host --ipc=host -v /var/lib/containers:/var/lib/containers -v /dev:/dev --security-opt label=type:unconfined_t [-v <mnt>:/target] <image> bootc install to-filesystem … /target` (docs' to-disk flag set; `system-reinstall-bootc` omits `--ipc=host` — pass it). Add `-v /:/target` for `to-existing-root` until tested (docs still show it; the clap doc says "now not necessary").
- From the MiOS live ISO, source from `containers-storage:<ref>` (osbuild stage / fisherman direct mode) with `--target-imgref <registry ref>` so day-2 `bootc upgrade` points at ghcr.io. No network needed (BAKE-NOT-FETCH).
- `mios-install` itself is a static binary shipped in the image, so it is present on the live ISO and on an installed host (for `existing-root` and `filesystem` modes). **Inference:** it can also be executed from inside the install container, but the orchestration (device discovery, repart, mount) is simpler from the host side with podman exec'd as a child.
- **Abandon** the current host-side `bootc install to-disk --source-imgref docker://…` flow rather than port it: docs require a chroot of the image; #1400 reports SELinux-policy and `prepare-root.conf` failures for host-run `--source-imgref`; #433/#879 remain open. Only fall back to host bootc + bubblewrap/chroot of the pulled image when podman is absent (Readymade does host bootc, but without the chroot — outside the documented envelope).
- Drop the `wipefs -a` + `sgdisk -Z` pre-steps: `--wipe` already does wipefs on children + device (baseline.rs:223-229), and their interaction with repart's `--empty=force` is untested.
- Keep `to-disk --wipe <dev>` as the first-shipped compatibility path (minimal MiOS code: exec-wrapper only), then move `disk` to the repart + `to-filesystem --skip-finalize` → inject → `finalize` route (fisherman/Readymade), which is what gives LUKS/btrfs/ESP-size control image-builder lacks.

### 3.6 Backend choice

Stay on the ostree backend with ostree-side composefs (`50-composefs.toml`, `ostree.composefs=1`) and bootupd→GRUB (assumed, unverified) for now. The composefs-rs backend (`--composefs-backend`, UKI, systemd-boot, 1024 MiB ESP, no bootupd) is "Experimental, but close to stabilization", on-disk formats "subject to change", zstd:chunked pulls broken on the pinned v0.9.2 (issue 2408 / composefs-rs PR 381; v0.9.3 not yet consumed). Keep the planner layout-agnostic so that switching to the composefs backend, or to a repart/sysupdate A/B layout, is a mios.toml change.

### 3.7 Migration path (ChromeOS pattern)

1. Ship `mios-install` as the entry point with the Python CLI contract, exec'ing `podman run … bootc install to-disk --wipe` (or the existing wrapper under `--mock`).
2. Absorb discovery/safety natively; add `existing-root` (copy `system-reinstall-bootc`).
3. Add repart-driven `disk` and `filesystem` with `--skip-finalize`/`finalize`.
4. Retire `baremetal_install.py`; update ADR-0014 (`--transport oci` → `--source-imgref oci-archive:…` + `--target-transport`).

## 4. Static-linking reality and the decision it forces

Facts:
- `bootc-lib` is not on crates.io (404) and "isn't actually published as a crate"; all installer option structs are `pub(crate)`. It links libostree-1 (`ostree 0.20.5` → `ostree-sys 0.15.3`, `links = "ostree-1"`, system-deps/pkg-config, dynamic libostree + glib/gio/gobject), `openssl 0.10.72`, `selinux =0.6.3` (libselinux), `libsystemd 0.7`, `zstd 0.14.0` with `pkg-config`, `rustix` with `use-libc`; `[profile.release] panic = "abort"` "We use FFI so this is safest"; vendor-filter `*-unknown-linux-gnu`; no musl/static mention anywhere in its build files. Fedora's RPM Requires confirm libostree-1.so.1, libglib/gio/gobject, libselinux.so.1, libssl/libcrypto, libz, libzstd plus ostree, podman, skopeo, composefs. Runtime execs skopeo (`containers-image-proxy`), ostree, bootupctl/bootctl, mkfs.*, sfdisk, podman.
- `ostree-ext`: same libostree dependency; crates.io copy frozen at 0.15.3 (2024-11-04), upstream repo archived.
- `system-reinstall-bootc`: pure fork/exec of podman, no C FFI beyond libc via rustix(use-libc); internal `bootc-internal-mount/utils` path crates are unpublished (vendor or re-implement); musl untested upstream.
- `composefs-rs` 0.9.x: no libostree/glib; `openssl` (vendorable), `zstd-sys` and `pcre2-sys` build bundled C via `cc`, `rustix` libc-free; no musl CI; crates on crates.io; still execs skopeo for registry pulls; formats "may still change".
- `bootupd` 0.3.2: no libostree; openssl + libsystemd crate; plausibly musl-static; install verb hidden/bootc-only.
- Static-safe toolbox: gptman 3.1.1, gpt 4.1.0, rustix::mount, sys-mount 3.1.0, lsblk 0.6.1 (pure sysfs), loopdev-3 0.5.3. Avoid libblkid-rs (dynamic libblkid, inferred from `pkg_config.probe("blkid")`). MiOS's lock already has zero openssl entries.
- systemd-repart / bootctl / cryptsetup are C tools; the only C-free IPC is Varlink (`io.systemd.Repart` on F44's systemd 259; `io.systemd.BootControl.Install` needs v260+, beyond the base).

Decision forced: **the MiOS installer cannot embed bootc; it must be an exec-wrapper.** The static-pie rule and Law 14 are satisfied only by a binary that owns planning, discovery, safety and config projection and execs `podman run <image> bootc install …` (plus `systemd-repart`, or its Varlink interface). The sole pure-Rust alternative — `composefs-oci` pull → `composefs-boot::write_boot_simple` → copy systemd-boot EFI binaries — is linkable in principle but requires dropping bootupd/GRUB from the base, rests on experimental formats, has no upstream musl proof, still execs skopeo, and hands day-2 upgrades to bootc's experimental backend; defer it to a spike. Do not link ostree/ostree-ext (libostree+glib), do not adopt rpm-ostree (maintenance mode) or systemd-sysupdate (non-OCI, API being replaced).

Trade-offs accepted: hard runtime dependency on podman and on the image's bootc CLI (1.16.x flag surface must be probed per release; #542 open); `to-disk` partition sizes are uncontrollable unless MiOS takes the repart + `to-filesystem` route; repart's branch inside bootc `to-disk` is unavailable in the shipped bootc (see §5).

## 5. Risks and open questions

### 5.1 Cross-lane contradictions the design must resolve first

- **Does bootc `to-disk` already use MiOS's `usr/lib/repart.d/50-root.conf`?** Lane 2 and lane 4 read `can_use_systemd_repart()` from **main** and concluded "MiOS installs already take the systemd-repart branch". The orchestrator must run repart itself (§3.1) until then. Whether `to-disk` with image-shipped repart.d honours `Format=` over `--filesystem`/`root-fs-type` was read from structure only, not exercised.
- **`00-mios.toml` validity.** Lane 3 flags `[install] root-fs-type = "ext4"` as a "LOCAL BUG CANDIDATE" that "likely fails to parse" under `deny_unknown_fields`.
