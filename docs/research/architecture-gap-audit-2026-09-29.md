## Claims corrected or still unproven

* The report calls `server.py` a 30,253-line file and says tokenization, context packing, preemption, and the model provisioner are absent. This tree has a roughly 4,200-line `usr/lib/mios/agent-pipe/server.py`, imports the named modules, and contains `usr/libexec/mios/mios-models-firstboot`. Integration and default settings remain separate questions.
* Composefs work is present in `automation/77-composefs-verity.sh`, `automation/93-composefs-seal.sh`, and `usr/lib/greenboot/check/required.d/15-composefs-verity.sh`; `usr/share/mios/mios.toml:1630` requests verity. A source audit cannot prove that the installed host booted with a verified root. Capture boot-time mount, digest, and greenboot evidence before calling this complete or broken. The [composefs project](https://github.com/composefs/composefs) describes the underlying mechanism.
* The [A2A specification](https://github.com/a2aproject/A2A/blob/main/docs/specification.md) requires an Agent Card but says it **may** be signed. Signed-card interoperability is useful work, but lack of a signature alone is not a protocol violation.
* The report's Blackwell IOMMU identity-map bypass, `pasta` race, Tetragon/Looking Glass contention, and fabrication test results lack reproducible host logs or a cited primary patch/test case in the supplied summary. Keep them as investigation candidates, not confirmed MiOS defects. Match any hardware claim to the actual device, kernel, IOMMU group, and failure log.

## Live-install boundary

This audit was made while the Windows bootstrap built its Fedora overlay in `podman-MiOS-DEV`. Source-tree findings do not imply that the in-progress image has passed its later build, boot, and application readiness stages. Use the unified install log and the MiOS monitor's Global Systems stream for that evidence.
